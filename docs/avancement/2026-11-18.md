# 2026-11-18

## Décisions
- Nom : **Rohy** (« lien, corde » en malgache).
- Réseau local uniquement pour l'instant ; chiffrement de bout en bout au niveau de l'app ; appairage par QR code.
- Android → Mac : tuile Réglages rapides, menu Partager, action de notification et menu de sélection de texte.
- Historique reporté après le MVP.
- Positionnement après l'étude concurrentielle (`docs/research/`) : confiance vérifiable, libre et gratuit,
  hygiène des secrets ; fonction « codes de vérification » conditionnée à la phase 05.
- Windows et Linux : Rust + iced (`docs/features/windows-linux.md`), après stabilisation.

## Réalisé
- Monorepo, spécification du protocole v1, vecteurs de test partagés Swift/Kotlin.
- App Mac de barre de menus (Swift) et app Android (Kotlin, Compose).
- Test d'interopérabilité du client Kotlin contre le vrai serveur Swift.
- Hooks `pre-commit` / `pre-push`, seuils de couverture, CI GitHub Actions.
- PR #1 (MVP) et #2 (CI) fusionnées ; dépôt transféré vers `kinga-org/Rohy`, CI au vert.

## Test réel (Galaxy S24 Ultra, Android 17, One UI 9 ; MacBook Pro, macOS 27)
- Premier essai : connexion impossible. Cause : Android bloque le trafic `ws://` non chiffré par défaut.
  Corrigé par une configuration réseau dédiée (les données restent chiffrées par l'app).
- Après correction : association, Mac → Android et Android → Mac fonctionnent ; Bonjour trouve le Mac.
- Ajout de « Envoyer au Mac » dans le menu de sélection de texte (sous ⋮).

## Problèmes rencontrés
- CI en `startup_failure` sur le compte personnel (probablement facturation) : résolu par le transfert dans l'org.
- Compose et OkHttp récents exigent l'API Android 37 (absente du SDK local) : versions compatibles API 36 épinglées.

## Non vérifié
- Latence de la tuile, tenue du service sur plusieurs heures, alerte presse-papiers de macOS 27.

## Phase 06 — fiabilité (après-midi)
- Ajouts : assistant « Garder la connexion » (états réels des réglages lisibles, raccourcis Samsung),
  reconnexion immédiate au retour du Wi-Fi, relance après démarrage et mise à jour, journal de connexion
  persistant, confirmation avant « Oublier ce Mac ».
- Découverte : sur Android 17, **déclarer** `ACCESS_LOCAL_NETWORK` suffit à bloquer le trafic local de l'app
  tant que la permission n'est pas accordée (même en ciblant l'API 36). Elle est maintenant demandée.
- Bugs corrigés : l'écran Android revenait à « Associer un Mac » après le scan (course avec le service) ;
  la fenêtre QR du Mac ne se fermait pas après l'association.
- Mesures sur le Samsung : reconnexion 1,2 s après le retour du Wi-Fi ; reconnexion seule après le
  redémarrage de l'app Mac ; service relancé seul après la mise à jour de Rohy.
- Gêne de développement : chaque compilation du Mac (signature ad hoc) redemande l'accès au trousseau ;
  contournement documenté dans le README (certificat Apple Development).
- Redémarrage du téléphone : reconnecté seul 1,4 s après la relance du service, sans ouvrir l'app.
- Non vérifié : endurance 24 h, fermeture de la fenêtre QR et écran Android
  après une nouvelle association (corrigés mais pas encore rejoués).
