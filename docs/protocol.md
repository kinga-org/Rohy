# Protocole Rohy v1

Ce document décrit le protocole entre l'app Mac (serveur) et l'app Android (client).
Les deux implémentations (`mac/Sources/RohyCore`, `android/core`) doivent rester conformes
à ce texte et aux vecteurs de test de `protocol/test-vectors.json`.

> Statut : non audité. Le protocole est volontairement simple et publié pour pouvoir être relu.

## Primitives

| Rôle | Primitive |
|---|---|
| Échange de clés | X25519 (RFC 7748), clés statiques de longue durée |
| Dérivation | HKDF-SHA256 (RFC 5869) |
| Chiffrement | ChaCha20-Poly1305 (RFC 8439), tag de 16 octets |
| Encodage binaire dans le JSON | Base64 URL sans remplissage (RFC 4648 §5) |

Chaque appareil possède une paire de clés X25519 générée localement et jamais exportée.

## Transport

- WebSocket sur le réseau local, `ws://<hôte>:<port>/rohy`. Port par défaut : `47823`.
- Le Mac annonce le service Bonjour `_rohy._tcp` avec l'enregistrement TXT
  `fp=<empreinte>` où l'empreinte est `hex(SHA-256(clé publique Mac))[0..16]`.
- Le chiffrement est assuré au niveau applicatif : le WebSocket lui-même n'est pas en TLS.

## Appairage par QR code

Le Mac affiche un QR code contenant l'URI :

```
rohy://pair?v=1&pk=<clé publique Mac>&t=<jeton>&n=<nom du Mac>&h=<ip1,ip2>&p=<port>
```

- `pk` : clé publique X25519 du Mac (32 octets, base64url).
- `t` : jeton d'appairage aléatoire de 32 octets, à usage unique, valable tant que la
  fenêtre d'appairage est ouverte sur le Mac.
- `n` : nom lisible du Mac (encodé en pourcentage).
- `h` : adresses IPv4 du Mac séparées par des virgules (repli si Bonjour échoue).
- `p` : port.

Le téléphone conserve `pk`, `n`, `h`, `p`. Le jeton n'est envoyé qu'une fois, chiffré.

## Poignée de main

1. Client → serveur, trame **texte** :
   `{"t":"hello","v":1,"pk":"<clé publique client>","n":"<nonce client 16 o>","name":"<nom du téléphone>"}`
2. Serveur → client, trame **texte** :
   `{"t":"welcome","v":1,"pk":"<clé publique Mac>","n":"<nonce serveur 16 o>","status":"trusted"|"pairing"}`
   - `trusted` : la clé du client est déjà connue.
   - `pairing` : clé inconnue mais une fenêtre d'appairage est ouverte.
   - Sinon le serveur ferme avec le code `4403`.
3. Le client vérifie que `pk` correspond à la clé reçue dans le QR code ; sinon il ferme (`4403`).
4. Les deux côtés dérivent les clés de session :

```
partagé = X25519(clé privée locale, clé publique distante)
sel     = nonce client ‖ nonce serveur
k_c2s   = HKDF-SHA256(partagé, sel, "rohy/v1 c2s", 32)
k_s2c   = HKDF-SHA256(partagé, sel, "rohy/v1 s2c", 32)
```

Les nonces aléatoires de session empêchent de rejouer une session précédente.

## Trames chiffrées

Après la poignée de main, toutes les trames sont **binaires** :

```
trame = nonce (12 o) ‖ texte chiffré ‖ tag (16 o)
nonce = 0x00000000 ‖ compteur (64 bits, gros-boutiste)
AAD   = "rohy/v1" (ASCII)
```

- Un compteur par sens, qui démarre à 0 et augmente de 1 à chaque trame.
- Le destinataire exige exactement le compteur attendu : toute trame rejouée, réordonnée
  ou falsifiée ferme la connexion (`4400`).

## Messages chiffrés (JSON)

| Message | Sens | Contenu |
|---|---|---|
| `pair` | client → serveur | `{"t":"pair","token":"<jeton>"}` ; obligatoire et premier si `status = pairing` |
| `paired` | serveur → client | `{"t":"paired","name":"<nom du Mac>"}` |
| `clip` | les deux | `{"t":"clip","id":"<uuid>","text":"<texte>","sensitive":false}` |
| `ping` / `pong` | les deux | `{"t":"ping"}` / `{"t":"pong"}` |

- Le serveur compare le jeton en temps constant. Un jeton faux ferme la connexion (`4403`)
  et le jeton est invalidé.
- Un message `clip` reçu avant l'appairage est refusé (`4403`).
- Taille maximale d'un texte : 1 Mio (au-delà, le message est ignoré par l'émetteur).

## Codes de fermeture

| Code | Sens |
|---|---|
| `4400` | Trame invalide (déchiffrement, compteur, JSON) |
| `4403` | Appareil non autorisé ou jeton invalide |
| `4426` | Version de protocole non prise en charge |

## Hygiène des secrets

- Mac : les contenus marqués `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`
  ou `org.nspasteboard.AutoGeneratedType` ne sont jamais envoyés.
- Android : un texte reçu avec `sensitive: true` est écrit avec `ClipDescription.EXTRA_IS_SENSITIVE`.

## Limites connues (v1)

- Clés statiques : pas de confidentialité persistante (forward secrecy) si une clé privée fuit.
- Pas de rotation de clés ni de révocation à distance (la révocation se fait sur le Mac).
